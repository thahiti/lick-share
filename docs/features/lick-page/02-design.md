# lick-page: 릭 상세와 넘기기 플레이어를 /lick/:id 한 화면으로 통합 디자인

작성일: 2026-11-13. 모델: opus (Fable 사용량 한도로 대행). 상태: 승인됨 (2026-11-13).
시안: `docs/features/lick-page/mockup.html` (Artifact 링크: https://claude.ai/artifact/PwLTBgge51JrSQoVNoTz7m)

시안은 상태마다 `<section>` 하나이고 세로 스냅이라 휴대폰에서 위로 넘기면 상태가 순서대로 나온다.
노란 띠는 시안 설명이고 실제 화면에는 없다.
시안의 악보는 SVG 선과 타원으로 흉내 낸 것이다. 실제 조판은 Score 렌더러가 폭을 재서 한다.
폰 상태는 태블릿 폭에서 보면 태블릿 티어(가운데 열, 줄당 2마디)로 바뀌고, 데스크톱 브라우저에서 보면 390px 미리보기로 보인다.
데스크톱 상태(`#s19-desktop`)는 1280x800 화면을 폭에 맞춰 줄여 넣었다.

## 상호작용

- 터치와 마우스
  - 넘기기: 페이저 세로 스냅. 위로 밀면 다음, 아래로 밀면 이전. 마우스 휠도 같다. 긴 릭은 본문 끝까지 내린 뒤 한 번 더 밀면 다음 장(S17). 페이저는 `overscroll-behavior: contain`.
  - 음표 탭: 그 음의 시작부터 재생(S5). 터치 영역은 Score 의 `<g data-note>` 그대로다. 화면에서 달라지는 것은 플레이헤드 위치와 멈춤 표시뿐이다.
  - 빈 곳 탭: 악보 프레임 안(패딩 포함)에서 음표 밖. 멈춤과 재개(S2, S6). 제목, 메타, 태그 줄의 탭은 재생과 무관하다. 멈춤 표시와 카운트다운은 탭을 막지 않는다.
  - 템포: 버튼 탭으로 팝오버를 열고 닫는다. 바깥 탭과 Esc 로 닫는다(지금 `TempoControl`). 팝오버가 열린 채 악보를 탭하면 팝오버만 닫히고 재생 상태는 그대로다. 장이 바뀌면 닫힌다.
  - 오버플로: More actions 탭으로 메뉴, Delete lick 으로 다이얼로그. 다이얼로그는 Cancel, 배경 탭, Esc 로 닫는다(지금 `DeleteLickDialog`). 메뉴가 열린 채 악보를 탭하면 메뉴만 닫힌다. 메뉴와 다이얼로그를 여는 동안 소리는 이어진다.
  - 액션 행: Duplicate & edit, 좋아요, Share. 360px 미만 폭에서 Share 는 아이콘만 보이고 접근 이름은 "Share" 다.
  - 닫기 버튼: 기획 구조 2 의 `depth` 규칙.
- 키보드(데스크톱)
  - 열리면 닫기 버튼에 포커스. 탭 순서는 닫기, 템포, More actions, 작성자 링크, 원본 링크, 태그 칩, Duplicate & edit, 좋아요, Share. 포커스 링은 지금 2px brand-outline.
  - ArrowDown 과 ArrowUp 은 한 장, Space 는 멈춤과 재개, Esc 는 닫기(swipe-play R13 과 같다).
  - 포커스가 템포 팝오버, 오버플로 메뉴, 삭제 다이얼로그 안에 있으면 페이지 키를 받지 않는다. range 의 화살표는 템포만 바꾼다(S19).
  - 팝오버나 메뉴나 다이얼로그가 열려 있으면 포커스 위치와 상관없이 Esc 는 그것만 닫고 페이지를 닫지 않는다.
- 오류 표시
  - 한 장 모드 로드 실패: `#s10-error`. 없는 릭: `#s23-notfound`. 깨진 악보: `#s23-badscore`.
  - 다음 페이지 실패: 마지막 장 태그 아래 "Couldn't load more" 와 Retry(swipe-play R9 그대로).
  - 좋아요 실패: "Like failed" 토스트와 되돌림. 삭제 실패: 다이얼로그 안 "Delete failed. Please try again."(상세와 같다).
  - 토스트: 액션 행 위 84px + safe-area(힌트와 같은 자리), ink 배경 paper 11px, radius 2, 1.6초. 힌트와 겹치면 토스트가 위에 그려진다.

## 레이아웃 티어

브레이크포인트는 지금 그대로 휴대폰(<640px), 태블릿(640~1023px), 데스크톱(>=1024px)이다.
색과 간격은 `src/styles/tokens.css` 의 토큰만 쓴다.

### 공통 (상단 바와 장 하나)

- 상단 바
  - 높이 56px. 패딩 6px 12px, 안의 컨트롤 높이 44px. 오버레이의 50px 보다 6px 크다(템포와 More actions 의 44px 터치 대상).
  - 왼쪽부터 닫기(34px 원, 1px ink), 카운터(11px mut2, tabular-nums), 출처 라벨(11px mut2, 남는 폭 전부, 한 줄 말줄임), 템포 버튼(`.c-tb-btn` 44x44, 12px 600, 테두리 없음), More actions(44x44, 작성자만). 간격 8px. 아래 테두리 없음.
  - 한 장 모드는 카운터와 출처 라벨 자리를 빈 공간으로 둔다. 깨진 악보 장과 로딩, 실패, 없는 릭 화면에는 템포 버튼이 없다.
- 팝오버와 메뉴
  - 상단 바 기준 absolute, top 100%, right 12px. 템포 팝오버 폭은 약 284px 이고 `max-width: calc(100% - 24px)` 라 좁은 폰에서는 range 가 줄어든다(최소 48px). 320px 폭에서 왼쪽 여백 24px 로 들어간다.
  - 지금 `TempoControl` 의 팝오버는 래퍼의 `left: 0` 기준이라 상단 바에서 쓰려면 기준을 상단 바로 옮긴다(예: 래퍼 `position: static`). 방법은 명세가 정한다.
- 페이저: 상단 바 아래 남는 높이 전부. 장 높이는 페이저 높이와 같다.
- 장 본문
  - 패딩 4px 16px 12px, 세로 간격 10px.
  - 위에서 아래로: 머리(제목 줄과 메타, 간격 4px), 유사 릭 안내, 악보 프레임, 태그 칩, 목록 끝 캡션 또는 Couldn't load more, 긴 릭 캡션.
  - 제목 줄은 제목 17px 600(줄 높이 1.3)과 배지 둘이 한 줄에 흐르고 넘치면 배지가 다음 줄로 간다.
- 악보 프레임: 1px ink, radius 12, 패딩 10px 12px, 툴바 없음. 악보 폭 = 장 폭 − 58px(거터 32, 테두리 2, 패딩 24).
- 액션 행: 높이 64px(패딩 10px 16px, 버튼 44px), 위 1px line. 그리드 `1fr auto auto` 로 Duplicate & edit 가 남는 폭을 다 쓴다.
- 힌트와 토스트: 장 영역 기준 가운데, 아래에서 84px + safe-area.

## 열린 질문

Q1. 돌아온 목록에서 "앱 바 바로 아래" 를 어떻게 맞출 것인가.
- 배경. 2026-11-13 결정은 "넘겼으면 마지막으로 본 릭의 카드가 앱 바 바로 아래" 다. 그런데 모바일 앱 바(`.c-mappbar`)와 데스크톱 앱 바는 sticky 가 아니라 목록을 내리면 함께 올라간다. 다섯째 카드처럼 아래쪽 카드로 스크롤하면 앱 바는 화면에 없다.
- 예시. Latest 셋째 카드에서 열어 두 장 넘기고 돌아온다.
  - A(시안). 다섯째 카드의 윗변이 화면 위 12px 에 온다. 앱 바는 위로 올라가 보이지 않는다. 첫 카드도 같은 규칙이라 앱 바가 가려진다.
  - B. 다섯째 카드의 윗변이 목록 맨 위에 있을 때의 자리(앱 바 55px + 12px = 67px)에 온다. 그 위 67px 에는 넷째 카드의 끝(작성자와 좋아요 줄)이 보인다.
  - C. 모바일 앱 바를 sticky 로 바꾸어 글자 그대로 앱 바 바로 아래에 둔다. 모든 목록 화면의 동작이 바뀌므로 이 기능의 범위를 넘는다.
- 파급. A 와 B 는 FeedList 복원 마운트의 스크롤 목표 식만 다르다. C 는 앱 바 CSS 와 feed-cache 의 scrollY 기준(앱 바 높이만큼 어긋남)에 영향이 있다.
- 추천. A. 들은 릭 다음부터 이어 보는 것이 목적이라 카드가 화면 맨 위에 와서 아래 카드가 가장 많이 보이는 쪽이 낫고, 식이 가장 단순하다.
- 답(2026-11-13). A. 사용자가 추천대로 골랐다. 마지막으로 본 카드의 윗변을 화면 위 12px 에 둔다.
