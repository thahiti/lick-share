## 시나리오 기준 (S-n)

기획의 종료 시나리오를 Given, When, Then 으로 옮긴 것. 이 기능의 종료 조건이다.
전체 트랙은 `.claude/skills/verify/SKILL.md` 방식의 Playwright 스크립트로 개발 서버에서 실행하고 스크린샷을 남긴다.
경량 트랙은 명령과 출력(`npm run dump`, 단위 테스트)으로 실행한다.
시나리오마다 검증 증거로 남길 스크린샷 파일명을 적는다.

S1. Given ... When ... Then ... 증거: `s1-after.png`.
S2. ...

## 단위 기준 (AC-n)

규칙을 함수 수준에서 고정한다. 테스트 이름에 이 id 를 넣는다. 예: `AC-3 같은 이름은 대소문자만 달라도 거절한다`.

AC-1. Given ... When ... Then ...
AC-2. ...

## 구현 태스크

설정 파일이나 코드 계층이 아니라 독립적으로 검증 가능한 동작 단위로 나눈다.
태스크 하나가 끝나면 실행 가능한 결과가 하나 더 생기고, 어떤 시나리오가 처음으로 동작하는지 적는다.
태스크의 사이클은 "구현 → 단위 테스트 → 개발 서버에서 실제 실행 → 해당 S-n 통과 → 커밋" 이다.

| id | 동작 | 포함 AC | 처음 동작시키는 S | 완료 조건 |
|---|---|---|---|---|
| T1 | ... | AC-1, AC-2 | S1 | 단위 테스트 통과, S1 스크린샷 |

## 테스트 목록

| id | 종류 | 파일 |
|---|---|---|
| S1 | 시나리오 | Playwright 스크립트(스크래치패드), 증거 `harness/evidence/<id>/s1-after.png` |
| AC-1 | 단위 | src/community/api/xxx.test.ts |

## 검증 증거

verify 단계에서 `harness/evidence/<id>/` 에 남길 것.
- `check.txt`: `harness/check.sh` 출력.
- 시나리오별 스크린샷(전체 트랙). 파일명은 시나리오 기준에 적은 대로.
